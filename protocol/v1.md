# Protocol v1

## Common rules

- All timestamps are UTC RFC 3339 strings.
- IDs are UUIDs except Steam IDs and lobby IDs.
- The helper rejects protocol versions other than `1`.
- A game build hash accompanies every IPC request. Build `24397771` is the only documented research target; no hook is enabled by this repository.

## Named-pipe framing

The DLL and helper use `SharedSave.<game-pid>`, a byte-mode named pipe. Each frame is a 4-byte unsigned little-endian length followed by UTF-8 JSON. Frames over 1 MiB are rejected.

Every request has this envelope:

```json
{"version":1,"secret":"base64url-32-bytes","gameBuild":"24397771","command":"health","payload":{}}
```

The secret is generated by the launcher DLL with a CSPRNG, passed to the child helper only at process creation, and never persisted. The helper also checks the named-pipe client's executable against the configured game executable.

Commands currently implemented: `health`, `snapshot`. The remaining commands are reserved: `status`, `createSharedWorld`, `claimHost`, `renewHost`, `releaseHost`, `downloadLatest`, `listSnapshots`, `rollback`, `inviteMember`.

## Worker API

`POST /v1/sessions` accepts `{ "steamTicket": "base64" }` and returns a short-lived bearer session. The Worker verifies the ticket against Steam's server API using its secret key; it never trusts a caller-supplied Steam ID.

All other endpoints require `Authorization: Bearer <session>`.

- `POST /v1/worlds`: create a world.
- `GET /v1/worlds/:worldId/status`: membership and current lease.
- `POST /v1/worlds/:worldId/members`: owner-only member update.
- `POST /v1/worlds/:worldId/lease/claim`: atomically claim an expired lease.
- `POST /v1/worlds/:worldId/lease/renew`: renew with lease token and lobby ID.
- `POST /v1/worlds/:worldId/lease/release`: release with lease token.
- `POST /v1/worlds/:worldId/snapshots`: commit metadata after Drive upload, with lease token.

Lease tokens are opaque random values generated by the Worker and stored only as SHA-256 hashes.
